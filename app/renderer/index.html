Understanding ICMP Flood Attacks

INTERACTIVE CYBERSECURITY LESSON & SIMULATION GUIDE
🛎️ THE HOOK

What Happens When a Server Gets Pinged Too Much?

Imagine answering thousands of doorbells at once. Eventually, even a powerful server struggles to respond to genuine users. That's the core idea behind an ICMP flood.

👾 Attacker Bot SURGE 35k PPS
PING PING PING PING
REQ (LOGIN) ⚠️ TIMEOUT
🖥️ Target Server 🔥 CPU 96%
⏳ Legitimate User 504 TIMEOUT

📖 Core Terminology Breakdown

Click any card to inspect its real-world analogy and role in the attack:
📡
ICMP
PROTOCOL

Internet Control Message Protocol — used for network diagnostic error reporting.

Everyday Analogy: The postal return receipt stamped "Address Not Found" or "Delivered".
🛎️
Echo Request
TYPE 8

A diagnostic ping asking: "Are you online and reachable right now?"

Everyday Analogy: Knocking on someone's front door to check if anyone is home.
💬
Echo Reply
TYPE 0

The server's response confirming: "Yes, I am here and reachable."

Everyday Analogy: Opening the door and waving back: "Yes, I am here!"
⚡
ICMP Flood
ATTACK

Excessive volume of pings consuming processing capacity and disrupting legitimate traffic.

Everyday Analogy: Hundreds of people buzzing the doorbell at the same second.
⏱️
PPS
METRIC

Packets Per Second — incoming packet rate triggering hardware and kernel interrupts.

Everyday Analogy: A speedometer measuring how many knocks strike the door each second.
🧠
CPU Usage
RESOURCE

Processor computation power spent servicing network interrupt requests (SoftIRQs).

Everyday Analogy: Staff energy completely drained from answering nonstop doorbell rings.
🚫
Denial of Service
STATE

Condition where authentic, legitimate users are blocked from accessing the application.

Everyday Analogy: Genuine students walk away because the admissions office door is blocked.

🎯 Key Takeaways & Simulation Setup

1
Interrupt Starvation: The real culprit is not just bandwidth; processing millions of packets interrupts CPU tasks.
2
Connectionless Simplicity: ICMP has no three-way handshake, allowing single machines or botnets to flood effortlessly.
3
Defense in Depth: Mitigating flood attacks requires rate limiting, packet filtering, or upstream Anycast cloud scrubbing.
